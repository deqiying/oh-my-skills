# oh-my-skills

**把常用的 Agent 工作方法，整理成可维护、可跨项目复用的 skills。**

这是我的个人技能库：集中维护工程协作、Git 操作、设计讨论和项目文档等工作流。每个技能以 `SKILL.md` 为入口，按需携带引用文档、模板、脚本和资源，不绑定某一个业务项目。

## 技能目录

| Skill | 解决什么问题 |
|---|---|
| [guidelines](skills/guidelines/SKILL.md) | 控制工程改动范围，先核实事实，以最小充分改动完成目标，并进行相称验证。 |
| [git-operations](skills/git-operations/SKILL.md) | 明确 Git 操作的授权边界，检查工作树与暂存区，安全地分支、提交和同步。 |
| [grill-with-docs](skills/grill-with-docs/SKILL.md) | 通过设计访谈澄清方案，将确认的领域术语与长期决策记录到目标仓库。 |
| [maintain-project-docs](skills/maintain-project-docs/SKILL.md) | 维护项目现状 docs 与决策 notes，覆盖单项目、前后端同仓及 Monorepo。**完善中。** |

> `maintain-project-docs` 已有主要规范与模板，配套脚本、引用完整性和回归验证仍待收尾；暂不作为完成验证的技能发布。

## 从一个技能开始

1. 从上表选择技能，阅读它的触发条件、适用范围和授权要求。
2. 按所用 Agent 的本地技能加载方式，引用或安装完整的 `skills/<name>/` 目录；不要只复制 `SKILL.md` 而遗漏它需要的资源。
3. 在目标项目中使用，并优先遵循该项目已有的协作约定。

例如，在已加载 `guidelines` 的会话中：

```text
请使用 guidelines 完成这项修改：先检查真实实现，控制变更范围，
执行与风险相称的验证，并说明结果和未验证的边界。
```

本仓库维护技能源文件，不自动安装技能、不覆盖本机已有版本，也不替目标项目配置 CI。具体加载方式和运行依赖以所用 Agent 及各技能说明为准。

## 仓库结构

```text
skills/
  <skill-name>/
    SKILL.md       # 技能入口、触发条件与工作流
    references/    # 按需阅读的详细规则
    templates/     # 可复用的文档或配置模板
    scripts/       # 校验、生成或辅助操作
    assets/        # 图标、图片等静态资源
    agents/        # 特定 Agent 的元数据，按需提供
README.md          # 项目介绍与技能目录
AGENTS.md          # 本仓库的维护约定
```

每个技能只创建实际需要的目录；上面的资源目录不是必填清单。正式内容以 `skills/` 为准。

本地可能暂存 `write-notes-like-deepseek/` 作为参考。它已被根级忽略规则排除，不属于正式技能，也不得成为构建、校验或安装依赖；后续移出不会改变本仓库的正式目录结构。

## 维护方式

- **新增技能**：在 `skills/` 下建立独立目录，明确触发场景、操作流程和限制，再更新上方目录。
- **修改技能**：同步直接受影响的引用、模板和脚本；优先保持项目无关，不写入本机专属路径或凭据。
- **验证改动**：检查入口元数据、相对链接和资源完整性；包含脚本时补充与改动相称的实际测试。
- **保持轻量**：不为凑齐结构创建空文件，不把安装缓存、业务项目数据或临时参考仓库收进正式内容。

具体协作、授权和交付要求见 [AGENTS.md](AGENTS.md)。
